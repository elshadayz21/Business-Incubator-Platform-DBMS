# DxValley ICMS — Deployment Guide

Deploy **backend + database + public website** on **Render**, and optionally the **admin React portal** on **Vercel**.

---

## Architecture

| Part | Host | URL example |
|------|------|-------------|
| Public site (EJS) | Render | `https://dxvalley-icms.onrender.com` |
| API + sessions | Render | same URL |
| Admin / Mentor / Entrepreneur UI | Render **or** Vercel | `/admin` on Render, or `https://your-admin.vercel.app` |
| PostgreSQL | Render | internal `DATABASE_URL` |

> **Note:** The public homepage uses **server-side EJS templates**. It cannot be hosted as a static site on Vercel without a major rewrite. Render runs the full Node app.

---

## Part 1 — Render (Backend + DB + Public Site)

### 1. Push code to GitHub

Make sure your branch is on GitHub (`elshadayz21/Business-Incubator-Platform-DBMS`).

### 2. Create Render services

1. Go to [render.com](https://render.com) → **New** → **Blueprint**
2. Connect your GitHub repo
3. Render reads `render.yaml` at the repo root and creates:
   - **Web Service:** `dxvalley-incubator-backend` (Node, root dir `backend`)
   - **PostgreSQL:** `dxvalley-db`

### 3. Set environment variables (Render dashboard → Web Service → Environment)

| Variable | Value |
|----------|--------|
| `NODE_ENV` | `production` |
| `SESSION_SECRET` | long random string (auto-generated by blueprint) |
| `DATABASE_URL` | auto-linked from `dxvalley-db` |
| `BASE_URL` | `https://YOUR-SERVICE.onrender.com` |
| `CORS_ORIGINS` | your Vercel admin URL, e.g. `https://dxvalley-admin.vercel.app` (only if using Vercel for admin) |

### 4. Run database migrations

After the first deploy, open **Render Shell** for the web service:

```bash
cd backend
npm run migrate
```

### 5. Seed admin user (if empty DB)

If you need initial users, run your seed script or import from local DB.

### 6. Verify

- `https://YOUR-SERVICE.onrender.com` → public homepage
- `https://YOUR-SERVICE.onrender.com/admin` → admin login (when not using Vercel)

## Part 2 — Vercel (Admin UI only — optional)

Use this if you want the React admin portal on a separate Vercel URL.

### 1. Import project on Vercel

- **Root Directory:** `frontend`
- **Framework:** Vite
- **Build Command:** `npm run build:vercel`
- **Output Directory:** `dist`

(`vercel.json` in `frontend/` already configures this.)

### 2. Environment variables (Vercel)

| Variable | Value |
|----------|--------|
| `VITE_API_URL` | `https://YOUR-SERVICE.onrender.com` (no trailing slash) |

### 3. Update Render CORS

On Render, set:

```
CORS_ORIGINS=https://your-admin.vercel.app
```

Redeploy Render after changing env vars.

### 4. Login

Open your Vercel URL → login uses Render API with session cookies (`SameSite=None`, `Secure` in production).

---

## Part 3 — All-in-one on Render (simplest)

Skip Vercel entirely:

1. Deploy only on Render (steps in Part 1)
2. Do **not** set `CORS_ORIGINS` or `VITE_API_URL`
3. Use `https://YOUR-SERVICE.onrender.com/admin` for admin/mentor/entrepreneur portals

This is the **recommended** setup for this project.

## Local development

```bash
cd backend
cp ../.env.example .env   # fill in DB_* values
npm install
cd ../frontend && npm install && cd ../backend
npm run build              # build admin into backend/public/admin
npm start                  # http://localhost:3000
```

## Troubleshooting

| Problem | Fix |
|---------|-----|
| 502 / app won't start | Check Render logs; verify `DATABASE_URL` and migrations ran |
| Admin login fails on Vercel | Set `VITE_API_URL` on Vercel + `CORS_ORIGINS` on Render |
| Session not persisting cross-origin | Both must use HTTPS; `CORS_ORIGINS` must match Vercel URL exactly |
| Free Render sleeps | First request after idle may take ~30s (cold start) |
